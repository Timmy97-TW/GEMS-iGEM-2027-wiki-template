# GEMS Taiwan iGEM 2027 Wiki Template

The starting point for next season's wiki. Pages, URLs, navigation, layout and components are all built; every piece of content is a placeholder. Each page has boxes saying what the judges look for, so you can fill it in by following them.

**Live preview: <https://timmy97-tw.github.io/GEMS-iGEM-2027-wiki-template/>** (updated automatically by `.github/workflows/pages.yml` on every push to `main`)

**This repo is a public GitHub template, not the copy the judges see.** Judges only look at the version deployed on iGEM's own GitLab. The GitHub Pages preview and anything at any other address is not judged.

## Running it in five minutes

Needs Python 3.8 or later and nothing else.

```bash
python3 tools/build.py                       # update nav and footers from pages.json
python3 -m http.server 8791 --directory site # then open http://localhost:8791
python3 tools/check.py                       # run the checks
```

## Page list

24 pages: 19 required by iGEM (13 standard URLs plus the 6 default pages of the official template) and 5 that GEMS writes every year (Parts, Dry Lab Notebook, Laws and Regulations, Attributions, Milestones). Topic-specific pages are not in the template; add them once the topic is chosen.

```bash
python3 tools/build.py --list
```

**Do not delete the page for an award you are not entering.** Keep it with one line saying "Not selected this year", or at least keep its URL in `pages.json`. If a standard URL changes, that award is not judged. The checker blocks this.

## How to write a page

1. Read the comment at the top of the page and fill in the P numbers. Do not change the W-ID.
   ```
   W-ID: W003
   Content owner: P___
   Coding owner: P___
   Cross-checker: P___
   ```
2. Write the Master doc in Drive first, then move it into the HTML. Section headings must match the page. Each page has exactly one Master doc, edited only by the page owner; everyone else comments or opens an Issue.
3. Read each `<aside class="guide">` before deleting it. Replace placeholder paragraphs with real text, **and remove `data-ph` too**, or the checker will treat it as unwritten.
4. Make figures and numbers as described under "Components" below. If a figure or fact is not marked "Ready to publish" TRUE in Hub Figures or Facts, it cannot go up.
5. Using an outside person's name, photo, quote or logo needs a K from Hub Consent with status "agreed".
6. Run `python3 tools/check.py --page W003`.

AI may help rephrase sentences, lay out pages and debug. It may not produce results, data, citations or anything someone else said. Wrap AI-drafted text in `class="ai"`, which is highlighted while drafting; the person responsible rewrites it, removes the class, and discloses the AI use in the AI field of the Attributions Form. The official rules are at `igem.org/legal?tab=ai-policy-teams`.

## How to add a page

Add topic-specific pages, once the topic is chosen, with:

```bash
python3 tools/build.py new my-topic --title "My Topic" --tab project --caption "Three to five words"
```

`--tab` is one of `project`, `wetlab`, `drylab`, `engagement`, `team`. This does four things: assigns the next W-ID, adds it to `pages.json`, generates `site/my-topic/index.html`, and updates the nav and footer on every page.

Then you do two things:
1. Add a row in Hub Pages and fill in the owners.
2. Ask Ops to create the folder under `50 Deliverables/Wiki`, named as in the page's `drive_folder` in `pages.json`.

A supporting page must be linked from the relevant standard page. Judges will not go looking for it, and do not have to read it.

## Components

Everything is written directly in HTML, with no framework. There are examples on the pages: DBTL on `engineering`, the notebook on `notebook`, the timeline on `milestone`, member cards on `team`, stakeholder cards on `human-practices`, and the contribution table on `attributions`.

**Figures (need an F).** File name `F0031_W003_TopicA_v02.svg`. Put it in Drive `40 Media/Figures/Current` first, then upload it to `static.igem.wiki` with iGEM's uploads tool. Figure numbers are generated automatically.

```html
<figure class="fig" id="F0031" data-fig="F0031" data-page="W003">
  <img src="https://static.igem.wiki/teams/TEAM_ID/wiki/F0031_W003_TopicA_v02.svg" alt="What this figure shows" loading="lazy" />
  <figcaption><span class="fig__label"></span> Caption, with n and the statistical method. <span class="fig__id">F0031</span></figcaption>
</figure>
<a class="figref" href="#F0031"></a>   <!-- in-text reference; becomes "Figure 1" -->
```

Remember to remove `fig--pending` and replace `.fig__slot` with the `<img>`. Decorative images are not evidence: write `<img data-decorative alt="">`.

**Numbers (need a V).** No number, name or quote goes on the wiki without a V.

```html
<span class="fact" data-v="V0042">12.3 unit</span>
```

**Citations.** Writing `[3]` in the text links to the third entry in the `.refs` list automatically, with a link back.

**Attribution lines.** `<p class="attr"><b>Attribution.</b> Designed by ...</p>`, at the end of an experiment or model section.

**DBTL.** One `.cycle` per cycle, with four boxes (Design, Build, Test, Learn) and the R, F, V and D underneath.

**Notebook.** One `.nb-entry` per entry, with the date in `data-date` and the R in `data-run`. The page builds the month filter and keyword search automatically.

**Timeline.** `<ol class="timeline">`, one `<li>` per entry, with the real date in `<time>`.

**Member cards.** Edit `site/assets/data/roster.js`; instructions are at the top of the file. Photos need a K.

**Stakeholder cards.** One `.ihp-card` per interaction, with `data-interaction` and `data-consent`. Without a K, give only the person's role.

## Changing the theme

Change only `--brand-*` and `--accent` in `site/assets/css/tokens.css`. Hard-coded colours anywhere else in the CSS are blocked by the checker.

By default the site uses the reader's built-in system fonts, so nothing is downloaded. To use a team font, upload it to `static.igem.wiki`, uncomment the `@font-face` block at the top of `tokens.css` and change `--font-body`. **Do not link Google Fonts.** A CJK font that is not subset can be 10 to 20 MB, so subset it to the characters you use.

For libraries such as KaTeX or three.js, put the JS and CSS in `site/assets/` and upload any fonts they need to `static.igem.wiki`. Check the size first: the artifact limit is 10 MiB.

## The checker

```bash
python3 tools/check.py            # everyday use; fails only on ERRORs
python3 tools/check.py --page W003
python3 tools/check.py --freeze   # placeholders count as failures; must pass fully before N30
```

| Blocks (ERROR) | Lists (to-do) |
|---|---|
| A required page is missing or a standard URL changed | Guide boxes still present |
| A `<figure>` with no F or no caption; an `<img>` outside a figure | Placeholder text, `[Bracketed placeholder prose]` |
| A number marked `.fact` with no V | `F____`, `V____` |
| A footer missing the licence or repo link | IDs such as `R____`, `K____` |
| Resources loaded from outside iGEM | An owner still set to `P___` |
| An internal link or asset that does not exist | `PROJECT_NAME`, `TEAM_ID` |
| Images, fonts or video in the repo | `draft_marks` still on |
| A colour outside `tokens.css` | `class="ai"` still present |
| `site/` over 10 MiB | |

GitLab CI runs it first and does not deploy if there is an ERROR. It can only check structure: it cannot tell whether a number is right, or whether a V is really ready to publish. That is the job of the Cross-checker and the instructors.

## Deploying to iGEM GitLab

iGEM creates the team repo with the official Flask template in it. Replace it with this one:

```bash
git clone https://gitlab.igem.org/2027/gems-taiwan.git    # use the URL in iGEM's 2027 announcement
cd gems-taiwan
git rm -r --quiet .                                       # clear out the official template
git checkout HEAD -- LICENSE                              # keep the official LICENSE; it must not change
# copy in everything from this template except .git and LICENSE
python3 tools/check.py
git add -A && git commit -m "Start the 2027 wiki from the GEMS template"
git push origin main
```

CI copies `site/` into `public/` and deploys to `https://2027.igem.wiki/gems-taiwan/` in about 30 seconds. Only `main` deploys.

Three things to watch:
- **A single push may not exceed 11 MiB.** Split it if it is too big. Images should not be in the repo, so this should not normally happen.
- **Test once on the iGEM platform.** We have no 2027 repo yet, so this deployment path has not run on iGEM. In the first week of the season, push the empty template once and confirm that `/contribution` (no trailing slash) opens and the CSS loads.
- **Change URLs and the team name only in the `site` block of `pages.json`.** Then run `python3 tools/build.py`.

**Checking for external resources:** iGEM has an External Content Checker (`teams.igem.org/go/deliverables/wiki/har-check`). Run it on every page before the freeze.

## First week of the season (Wiki Lead)

1. Create a new repo with "Use this template", under the team organization, not a personal account.
2. Read iGEM's 2027 announcements: standard URLs, awards, footer, external resources, size limits, dates. If anything changed, update `pages.json`, `STANDARD` in `tools/check.py`, and this README.
3. In the `site` block of `pages.json`, fill in `project_name` and `igem_team_id`. Take `team_slug`, `wiki_url` and `gitlab_url` from what iGEM gives you.
4. Load the W-IDs and Master doc names into Hub Pages and fill in the owners. Node N14 requires an owner for every page.
5. Push once to GitLab and run the test above.

## How it connects to the rest of the system

| What | Where | Who owns it |
|---|---|---|
| Who owns which page, status, open failures | Hub `Pages` | Wiki Lead |
| Issues and fixes (the only list during the sprint) | Hub `Issues` | Anyone opens; Wiki Lead triages |
| Figures | Hub `Figures`, files in `40 Media/Figures/Current` | The figure's author; Cross-checker checks; instructor signs off |
| Numbers | Hub `Facts` | Whoever proposes it; Cross-checker checks; instructor signs off |
| Text source | `50 Deliverables/Wiki/W### PageName/W###_PageName_Master` | Content owner |
| Code | This repo | Coding owner |

The full chain: `R` → `V`, `F` → `W`. **No figures pasted into Word, no new lists for fixes, no personal upload folders.**

Related nodes (all dates are placeholders): N14 site and facts v1, N27 figures final, N30 last push for the whole site, N31 freeze.

## Handing over to next season

After the freeze the wiki is locked. Do these before close-out (N35):

1. Bring improvements other than content (components, the checker, page guidance) back into this template. **Do not bring that year's project content back**: no project name, science, sequences, results, names, photos, stakeholders or figures.
2. Run `python3 tools/check.py`, then grep the whole repo for that year's project name and list of names to confirm nothing is left.
3. Update the rules baseline table with the date you checked it.
4. Transfer ownership of the repo and Drive to Ops, following the Handover Checklist.
5. Write down the three things that were hardest to maintain that year, for next season's Wiki Lead handover note.
